`.ai-instructions.md` is the canonical instruction file. `AGENTS.md`, `CLAUDE.md`, `copilot-instructions.md`, `GEMINI.md`, and `QWEN.md` are symbolic links to it. Edit only `.ai-instructions.md`, never the linked files separately.

Documentation locations:

Keep its audit plans, registers, ontology vision, dossier reviews, and AI work in `docs/ep/`, with permanent documents distinguished from scratchpads.

The most recently updated Markdown file in `docs/wip/` is the current CorpusBuilder scratchpad; for emerging-philosophy work it is the most recently updated file in `docs/ep/`. Generate suitably named files as needed. Put completed AI documentation in `docs/ai/` or `docs/ep/` as appropriate, and never put scratchpad/WIP files directly in `docs/`.

## Environment, Commands, and Style

Core versions are Ruby 2.6.10, Rails 4.2.11.3, and SQLite3 1.3.13. Use `Gemfile.lock` for exact gem versions. rbenv manages Ruby. Bundler 1.17.3 has local patches enabling `bundle list --name-only` and avoiding the Ruby 2.6 `Gem::ConfigMap` deprecation problem; preserve those patches when upgrading or reinstalling it.

Always prefer project binstubs:

```bash
bin/rake test
bin/rake test TEST=test/models/philosopher_test.rb
bin/rake test TEST=test/controllers/questions_controller_test.rb TESTOPTS="-v"
bin/rake db:migrate
bin/rake db:schema:dump
bin/rake db:seed
bin/rake routes
bin/rake -T
bin/standardrb
```

Use `bin/rake`, not `rake` or `bundle exec rake`, and `bin/rails`, not `rails` or `bundle exec rails`. See `docs/RAKE_TASKS.md` for task documentation.

Do not preload default gems with command-line options such as `bin/bundle exec ruby -rjson`; they can activate Ruby's default gem before Bundler selects the locked version. Require libraries inside the Ruby code:

```bash
bin/bundle exec ruby -e 'require "yaml"; require "json"; ...'
```

Ruby 2.6 does not provide `Array#tally`; use a `Hash` counter.

Before starting a Rails server, check for an existing process with `ps aux | grep rails` or `lsof -i :3000`. Start `bin/rails server` only if needed.

Ruby 2.6.10 and Rails 4.2.11.3 have a Monitor incompatibility that can cause `ThreadError: already initialized` in controller tests. The automatic workaround is in `config/initializers/ruby_2_6_monitor_fix.rb`; alternative controller-test helpers are in `test/support/thread_error_workarounds.rb`, including `safe_controller_get()`.

Follow TDD: add regression tests before implementing features or fixes. Follow DRY and existing Rails naming and structural conventions. Use Ruby Standard style, ActiveRecord for database operations, specific exception handling, and `SecurityConfig` for dynamic method validation. Never add comments unless explicitly requested.

## Application Architecture

CorpusBuilder manages philosophical texts and linked metadata. The `shadows` table uses Single Table Inheritance for `Philosopher` and `Work`, with shared columns in `shadows` and extended or historical metadata in `PhilosopherAttrs`, `WorkAttrs`, and `ObsoleteAttrs`.

Key relationships and components:

- `Philosopher` and `Work` are associated through `Expression`; `Shadow` has many `Name` labels.
- `Text` and `Author` have a many-to-many relationship through `Writing`, which records roles such as author, translator, and editor.
- `Fyle` stores corpus file metadata and caching information.
- `Tag`, `Labeling`, `Filter`, and `MetaFilter` provide classification and querying.
- `Link`, `Property`, and `P::Smart` support RDF and Linked Data integration with Wikidata and DBpedia.
- `DateTimeMethods` provides date parsing; `SecurityConfig` centralizes security validation.

See `app/ERD.md` for the data model and `bin/rake routes` for the HTTP interface.

## Canonicity

**Status:** ✅ COMPLETE — genuine inputs restored and Phases 0–5 verified with corrected full-population publications on 2026-11-10. Work run `0.7.1` and dataset 6 contain synthetic test inputs and must never be published.

- **Algorithm:** Linear Weighted Combination with normalized importance weights. Scalar extrema, weighted source coverage, and derived components are normalized to `[0, 1]`; their product is the normalized measure.
- **Calculators:** `Canonicity::Philosopher::V2` and `Canonicity::Work::V2` are pure functions with no database queries or writes. Work applies genre once and both calculators guard zero denominators and invalid components through `Canonicity::Normalization.product`.
- **Configuration:** Weights are stored in `canonicity_weights`. Philosopher configuration `2.0` is historical-only because its weights can exceed 1; `2.1` is the default, with bitset weights summing to exactly 1.000000. Work uses `2.0-work`. Pre-flight rejects source weights above 1 for both subjects before run allocation, excluding Work genre multipliers.
- **Dense ranking:** `Canonicity::DenseRank` is shared by calculation, completion validation, replay, and publication. Equal measures share a rank and the next distinct measure increments once.
- **Evidence:** Immutable datasets and primitive records, subject-scoped runs, signal metadata, typed source events, frozen run configuration, and run-linked snapshots preserve reproducibility. Entity deletion does not erase evidence; ready datasets, completed runs, and publications are mutation-protected.
- **Population rules:** Capture requires selected IDs to be contained in normalisation IDs. Publication requires selected, normalisation, snapshot, and current subject populations to be identical.
- **Publication:** `Canonicity::Publication` revalidates eligibility under the cross-process lock, atomically updates current display values with bound ActiveRecord updates, and appends history. Republishing is allowed, interruptions roll back, and Work/Philosopher dependency mismatches warn without blocking on both dashboard and CLI.
- **Imports and capture:** Danker and reference-flag imports update inputs and source events atomically. Capture validates provenance and Work dependencies in one transaction, with interruption reconciliation and re-entrant locking. `Canonicity::CalculatorInput` adapts payloads using required-key fetches. A partial Danker file assigns `nil` to every omitted entity, never numeric zero.
- **UI:** `/canonicity` exposes configuration, signals, datasets, source events, runs, replay, comparison, publication eligibility/history, and dependency warnings. Snapshots are paginated at 100 rows and index eligibility batches population and snapshot queries.
- **Zero scores:** Zero is not a philosophical classification. Continually audit raw zero mention, role-suppressed positive mention, raw zero Danker, missing-value fallbacks, and zero-author adjustment using frozen payloads and calculation context. Preserve the distinction between `0.0` and `nil`; a missing philosophy mention is suspicious input evidence, not automatic grounds for exclusion.
- **Auditing:** Run-linked snapshots read frozen run weights. Model calculations do not create unlinked snapshots. `shadow:work:order2` and `shadow:philosopher:new_order` delegate only to explicit publication.

Controlled operations:

```bash
bin/rake metric:capture[Philosopher]
bin/rake metric:import_danker[file_path,Philosopher,source_version]
bin/rake metric:import_work_flags[file_path]
bin/rake metric:calculate[dataset_id,configuration_version]
bin/rake metric:recalculate[Philosopher,0.7.0,2.1]
bin/rake metric:runs
bin/rake metric:show[Philosopher,0.7.0]
bin/rake metric:replay[Philosopher,0.7.0]
bin/rake metric:compare[Philosopher,0.7.0,0.7.1]
bin/rake metric:publish[Philosopher,0.8.1]
```

`shadow:philosopher:metric` and `shadow:work:measure` use the same capture/run pipeline. Default Work capture selects the latest completed full-population Philosopher run, not a newer partial experiment. Tests and input-mutation scenarios use a copy or isolated database, never the live development database.

Current publications are Philosopher `0.10.0` (13,329 snapshots) and Work `0.7.2` (3,654 snapshots), both exactly replayable with zero display mismatches and no dependency warning. Genuine 2019 Danker restoration converted 903 legacy coerced zeros to `nil`, moving 210 philosophers and 626 Works off zero. ## Delta-of-Deltas

Delta-of-deltas detects convergence as the corpus grows, using Saffron-OS:

1. `delta_phases:saffron_runs` builds progressive corpus analyses.
2. `delta_phases:calculate_deltas` compares adjacent analyses using a selected diff strategy.
3. `delta_phases:delta_of_deltas` measures how those deltas change and checks the convergence threshold.

`delta_analysis:process_works` runs the standard workflow. See `docs/DELTA_OF_DELTAS_ALGORITHM.md` for the mathematics, parameters, outputs, and implementation details.

## Reference-Work Index and Metadata Leveraging

`import/sauce.rb` populates reference-work flags from scraped `*_tweak.txt` lists. It matches `Name` labels, validates birth/death dates, uses manual Q-ID mappings from `import/q_name.rb` for ambiguous cases, and sets the appropriate philosopher flag. Scraped lists are copyrighted and are not committed. See `docs/REFERENCE_WORK_FLAGS.md` for commands, matching rules, and troubleshooting.

Memcached is optional but substantially speeds repeated name matching. `Name.exact_label_count` and `Name.rough_label_count` are cached, as are queries in `lib/knowledge.rb`, `lib/knowledge/wikipedia.rb`, and `lib/knowledge/dbpedia.rb`. Operations degrade gracefully when Memcached is unavailable, with reduced performance.

## SQLite Gotchas

Rails 4.2 with SQLite can store booleans as `'t'`/`'f'` through ActiveRecord but `1`/`0` through raw SQL. Queries using `where(field: true)` may not match integer-backed values. Use ActiveRecord consistently for boolean writes and check representations when debugging empty results. See `docs/SQLITE_BOOLEAN_HANDLING.md`.

For exact floating-point reproduction, prefer bound ActiveRecord updates such as `update!`. In this SQLite stack, `update_all` can inline a float as SQL text and change its final bit, as found and fixed during Phase 4 publication.
